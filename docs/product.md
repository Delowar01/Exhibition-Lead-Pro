# Product — Card Scanner Pro

The full product surface for Card Scanner Pro: the two portals plus every
stage-delivered feature area. This is the detailed reference; the repo-root
[`replit.md`](../replit.md) keeps only a one-line summary of each area.

**See also:** [AI Architecture](ai-architecture.md) for the AI/Workflow engine
internals and safety contract, [Architecture Decisions](architecture-decisions.md)
for role/tenant/subscription decisions, and
[Security & Privacy](security-and-privacy.md) for scope-privacy rules.

## Feature areas

- **Platform Portal** (`/platform`): view all tenant companies, manage subscriptions, see platform-wide analytics, user management
- **Admin Portal** (`/admin`): scan business cards (real AI OCR), manage contacts, qualify leads through Kanban pipeline, track events, manage team, view reports, AI contact enrichment, duplicate detection + merge (`/admin/duplicates`)
- **Org structure** (Stage 3 Phase 1): Departments (`/admin/departments`, self-ref parent + head), Teams (`/admin/teams`, belongs-to-department + leader + members), expanded employee org profiles (`employeeId`/`jobTitle`/`employmentStatus`/`joiningDate`/`managerId`/`departmentId`/`teamId`), Employee Directory (`/admin/directory`, `GET /users/directory`), and Org Hierarchy (`/admin/org-hierarchy`, `GET /users/hierarchy`). All tenant-scoped + additive. Org-data reads are `view`-gated (like the `users`/`team` module), not open.
- **Executive Dashboards & Analytics** (Stage 3 Phase 2): real-time performance view per org level. Web `/admin/analytics` (scope selector company/department/team/employee + date range); mobile "My Numbers" (`/my-numbers`, own scope + team toggle for leaders). 5 read-only GET endpoints (`/analytics/overview`, `/analytics/department?id=`, `/analytics/team?id=`, `/analytics/employee?id=`, `/analytics/scope-options`) returning a shared `ScopedAnalytics` shape. `reports:view`-gated, tenant-scoped, cross-currency-correct, served via the analytics micro-cache. Scope privacy: employee sees own only; team lead sees own team; dept head sees own dept; company overview is manager-only. No DB changes (aggregations over existing leads/contacts/scans).
- **Enterprise AI Sales Copilot** (Stage 5B): generates reviewable DRAFT sales artifacts from real CRM data — 8 output types (email, whatsapp, call_prep, meeting_prep, proposal, followup, coaching, summary) over 4 entity types (lead, contact, organization, business_card) via an APPLICABLE matrix (`services/ai-copilot.service.ts`). NEVER auto-sends and NEVER auto-writes the CRM — every output is a draft the user must explicitly copy/use. `followup`/`coaching` always produce a grounded DETERMINISTIC core (conf 100), with best-effort AI phrasing layered on top (source flips to `ai` only when the LLM succeeds); the other 6 are LLM-only and SOFT-DEGRADE to HTTP 200 with `content.unavailable` (never 500). Every output carries full provenance (source/provider/model/promptKey/promptVersion) and deterministic rows never masquerade as AI. Endpoints under `/ai/copilot` (`ai_copilot` module: view/generate/use): generate is `POST /ai/copilot/{entityType}/{id}/{outputType}` (outputType is a PATH segment; body optional — `language` (en/ar), `tone`, `messageType`, `variant`, `instructions`; tone/messageType/variant are folded into the LLM prompt as soft guidance via `buildHints`, never overriding safety rules), plus aggregated `GET /ai/copilot/{entityType}/{id}/panel` (available types + deterministic suggested action + coaching signals + Stage 5A insights + stored outputs) and `GET /ai/copilot/{entityType}/{id}` list. Route order: the 3-seg generate POST is registered LAST (so it can't swallow `/outputs/:id/use|dismiss`); the `.../panel` GET before the 2-seg list GET. Path-scoped guards mirror `/ai/insights` (tenant-only, read-only-blocked, audited). Web: `SalesCopilotPanel` on Contact/Lead/Company detail is panel-wired (renders suggested action + coaching signals + AI intelligence + drafts from `/panel`), has an EN/AR draft-language selector passed on generate, and Copy + OS email/WhatsApp handoff (`mailto:` no recipient / `wa.me` no number, honoring "no forced Gmail", never auto-sends) + `/admin/ai-copilot` review page + batch in BatchOperations. Mobile: `CopilotSection` on contact/pipeline detail is panel-wired (suggested action + coaching signals), generates in the app's current locale (EN/AR i18n), status-action gating uses real lifecycle states (generated/edited), and adds native email/WhatsApp OS handoff (`Linking`) alongside expo-clipboard copy. Batch (`services/ai-copilot-batch.service.ts`) is an in-process tenant-scoped job queue (202 + poll).
- **Enterprise Intelligent Capture Engine** (Stage 5E): additive upgrade to the business-card capture pipeline. `extractCardData` now returns per-field confidence + provenance (`fieldConfidences`/`extractionMethod`/`model`/`promptVersion`/`processingTimeMs`, card_extraction prompt v2) persisted on additive nullable `scans` columns (plus `captureSource`/`qualityScore`/`qualityMeta`/`validationStatus`) — verbatim OCR/original fields NEVER overwritten. Deterministic `lib/capture-validation.ts` (pure) validates + normalizes email/website/phone(+dial-code/E.164)/postal/company/country/address and offers gap-fill (`websiteFromEmail`, `countryFromDialCode`). `services/capture-intelligence.service.ts#analyzeCapture` composes validation + tenant-scoped contact/organization recognition (with contact/lead counts) + a duplicate warning + smart suggestions; AI industry classification SOFT-DEGRADES with full provenance (`aiDegraded` flag) and NEVER auto-links/auto-merges/auto-writes. Endpoints (read-only, `scans:view`-gated, static paths before `/:id`): `POST /scans/analyze`, `POST /scans/batch-analyze` (202 + poll, in-process queue `services/capture-batch.service.ts`), `GET /scans/batch/{jobId}`. Web `Scan.tsx` renders a "Capture Intelligence" panel (debounced auto-analyze on scan + edits, duplicate/contact/org surfacing, user-initiated Apply of suggestions with AI provenance badges). Mobile `scan-review.tsx` surfaces the same intelligence + Apply; `capture-camera.tsx` computes a best-effort on-device quality score (degrades gracefully on web/Expo Go) passed as `qualityScore`/`qualityMeta`; EN/AR i18n parity + RTL.
- **Enterprise AI Workflow & Automation Intelligence** (Stage 5F): additive intelligence layer that recommends workflow actions from real CRM data but NEVER executes them (no auto-assign/route/stage-change/send/CRM-write). Per-entity `POST /ai/workflow/{entityType}/{id}/analyze` (lead/contact/organization) composes DETERMINISTIC grounded cores (SLA risk, smart routing/owner, opportunity progression, suggested department/team/priority/due-date — computed strictly from CRM fields at confidence 100) with best-effort AI phrasing layered on top (source flips to `ai` only when the LLM succeeds; LLM soft-degrades, never 500), persisting reviewable rows in the ONE new table `ai_workflow_recommendations` (mirrors `ai_insights`; one row per company+entityType+entityId+recommendationType via unique index). Deterministic rows NEVER carry AI provenance. Review lifecycle: `POST /ai/workflow/recommendations/{id}/{accept,dismiss}` records approval (status + acceptedById + acceptedAt) but does NOT itself mutate the source CRM — any resulting write still goes through the existing manual endpoints. COMPUTED read-only siblings (not persisted, served via analytics micro-cache): `GET /ai/workflow/{overview,health,sla-risks,bottlenecks}` (org-scoped: scopeType=company|department|team|employee & id, scope privacy mirrors analytics — employee own / team-lead own-team / dept-head own-dept / company-wide manager-only) plus `POST /ai/workflow/simulate` (what-if reassign/follow_up/delay → baseline/predicted/deltas/assumptions/confidence, writes NOTHING) and batch (re)analysis (`POST /ai/workflow/batch` 202 + `GET /ai/workflow/batch/{jobId}` poll, in-process queue). New permission module `ai_workflow` (view/generate/accept); path-scoped guards `requireTenantUser` (platform_owner blocked — customer CRM fenced off) + `blockReadOnlyMutations` + `auditMutations("ai_workflow")`; startup `backfillAiWorkflowPermissions` restores access for pre-existing admin(view/generate/accept)/employee(view) rows without reseeding. Web: `WorkflowIntelligencePanel` on Lead/Contact/Company detail + manager `/admin/workflow` page (health/SLA/bottlenecks/simulate). Mobile: `WorkflowSection` on pipeline/contact/company detail with EN/AR i18n + RTL.
