Copy the signature HTML

This is the production markup. Every image points at https://www.elitemarcom.com/signature/, so upload the asset files there first (or change the URLs to wherever you host them).

"Copy rendered" places the visible signature on the clipboard, which is what the Gmail and Outlook signature editors accept. "Copy HTML" gives the raw source for Apple Mail, Thunderbird, a CRM template, or your IT team.

Install it

Open this page in a desktop browser, use the copy buttons above, then follow your mail client.

Gmail

  1. Click Copy rendered above.
  2. Gmail → Settings gear → See all settings → General → Signature → Create new.
  3. Paste into the editor, set it as the default for new emails and replies, then Save changes.
Gmail removes embedded CSS, so the card shows still. Links, colours and layout are kept.

Outlook

  1. Click Copy rendered above.
  2. Outlook → Settings → Accounts → Signatures → New signature.
  3. Paste, name it, choose it for new messages and replies, then Save.
Outlook for Windows shows the still card. Outlook for Mac and Outlook.com usually keep the animation.

Apple Mail

  1. Mail → Settings → Signatures → add one for your account and untick Always match my default message font.
  2. Paste the rendered signature. For full animation, replace the signature's HTML in the .mailsignature file in ~/Library/Mail/V10/MailData/Signatures/ with Copy HTML.
  3. Reopen Mail and compose a test message to yourself.
Apple Mail and iOS Mail keep embedded CSS, so the ring, shimmer and reveal play for recipients on Apple devices.

What recipients see

Animation is a progressive touch. The still fallback is the same design, so nothing depends on it.

Recipient's clientResult
Apple Mail (macOS), iOS Mail, Outlook for Mac, Thunderbird, Samsung MailAnimated: photo ring rotates, gold rule shimmers, rows reveal in sequence, icons lift on hover
Gmail (web and apps), Outlook.com, Yahoo MailStill card, full layout and colours
Outlook for Windows (desktop)Still card; rounded photo may show square on older versions
Any client with images offText only: name, title, phone, address, website and social link labels still read correctly

Client behaviour above is from published CSS-support data, not a device pass on this signature. Send yourself a test from each account before rolling it out.
