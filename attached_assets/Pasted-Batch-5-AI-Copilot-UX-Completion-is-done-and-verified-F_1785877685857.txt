Batch 5 — AI Copilot UX Completion is done and verified. Final report:

Architecture reused — All work builds on the existing Enterprise AI Layer (ai.service / ensureAiAllowed, ai-copilot.service upsert model, assistant conversations), the existing lead_activities timeline model, Orval-generated API clients, and the existing toast/i18n systems. No new AI providers, no AI-layer bypass, no second draft system.

Actions per output type (web Copilot panel) — Every output card has Copy (plain-text conversion per type: email → "Subject + body", WhatsApp → message text, structured types → key/value lines), Regenerate (per-card spinner, keeps type + language), and Save as Note (contacts and leads). Copy/Save are disabled while a draft is unavailable.

Save-as-Note routing — Contact context → new POST /contacts/{id}/notes (subject AI draft — <label>, provenance metadata {aiGenerated, aiOutputType}, timeline invalidated); lead context → existing lead activities endpoint. Gated on contacts/leads edit permission (primary_admin/platform_owner bypass).

Deliberate exclusions — Organization entities have no note action (no org-note model; adding one would be a schema change out of scope). The admin AI Command Center has Copy but no Save-as-Note (no entity context to attach a note to).

Save-as-Draft decision — No separate draft store was added: all 8 copilot output types already persist via the upsert model and Edit already persists editedContent; no send endpoint exists to draft against. Building an assistant-chat→draft bridge would have been a second draft system, which the spec forbids.

Regeneration-failure retention — On LLM failure, if the existing row has a usable draft it is returned untouched with a response-only generationFailed: true flag (toast: "Generation failed — previous draft kept"); otherwise the prior soft-degrade placeholder behavior is unchanged (200, never 500).

Web error/retry states — Copilot panel query failure shows an inline error with a working Retry; unavailable drafts show a "Try again" action; AI Assistant (contact workspace and Command Center) now retains a failed send as a visible bubble with the typed message preserved and a Retry button, instead of silently dropping it. Duplicate submissions are prevented via isPending guards.

Mobile — Send errors are classified (network / permission / server) with localized EN + AR messages (RTL-safe), rendered as an alert bubble with Retry; the failed message text is retained. Duplicate sends blocked by mutation-pending guards.
