STATUS DEFINITIONS

Use only these statuses:

COMPLETE

Use only when:

- The real implementation exists.
- Frontend and backend are connected where both are required.
- Data is persisted correctly where required.
- Authentication, permissions, tenant isolation, validation, and error handling are present.
- Relevant tests or reliable verification evidence exist.
- No important approved requirement remains missing.

PARTIAL

Use when:

- Meaningful implementation exists, but required parts are missing, disconnected, incomplete, untested, or not production-ready.

PENDING

Use when:

- The required implementation is absent.
- Only a placeholder, mock, static screen, unfinished route, unused schema, or documentation claim exists.
- The current implementation does not satisfy the approved requirement.

VERIFICATION REQUIRED

Use when:

- The code appears implemented, but completion depends on browser, production, APK, physical-device, payment-provider, DNS, email, webhook, third-party integration, or other external verification that is not proven.

SUPERSEDED / REMOVED BY APPROVED DECISION

Use only when:

- A later explicit approved decision replaced or removed the requirement.
- Provide exact evidence of that decision.

NOT APPLICABLE

Use only when:

- The requirement genuinely does not apply to the final approved product.
- Explain why.
