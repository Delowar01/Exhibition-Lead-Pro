# MULTI-LANGUAGE & GCC LOCALIZATION ENHANCEMENT

## Project

AI Exhibition Lead Capture Platform

## Scope

**MOBILE APPLICATION ONLY**

(No Admin Panel changes in this iteration)

Before implementing, review the existing localization, OCR, translation, and settings modules to ensure no regression occurs.

---

# 1. COMPLETE MULTI-LANGUAGE SUPPORT

## Current Issue

The application currently provides two language options:

* English
* Arabic

However, only English is fully functional.

Arabic is either incomplete or not applied consistently throughout the application.

---

## Required

Implement full multilingual support across the entire application.

### Default Language

* English

### Supported Languages

* English
* العربية (Saudi Arabic)

The Arabic translation must use **Professional Saudi Arabic** suitable for business users in Saudi Arabia.

Avoid literal machine translation or generic Modern Standard Arabic where Saudi business terminology is more appropriate.

Examples include professional terminology commonly used in Saudi government and enterprise applications.

---

## Scope of Translation

Every part of the application must support localization, including:

* Login
* Dashboard
* Home
* Capture
* Contacts
* Duplicate Management
* Follow-Up
* Meetings
* Pipeline
* Tasks
* Workspace
* Digital Business Card
* Settings
* Notifications
* Reports
* Event Management
* Validation Messages
* Error Messages
* Success Messages
* Confirmation Dialogs
* Date Labels
* Buttons
* Menus
* Tabs
* Statuses
* Filters
* Search
* Empty States

Nothing should remain untranslated.

---

## RTL Support

When Arabic is selected:

* Entire application switches to Right-to-Left (RTL).
* Navigation should mirror correctly.
* Icons that require direction should also mirror where appropriate.
* Layout should remain premium and consistent.

Switching languages should update immediately without requiring the user to log out.

---

# 2. INTELLIGENT OCR TRANSLATION

## Objective

The OCR engine must intelligently preserve Arabic and English while translating other languages appropriately.

---

## Rule 1 – Application Language = English

When the application language is English:

Translate all captured fields into English.

Examples:

Arabic Company Name

↓

English Company Name

French

↓

English

German

↓

English

Chinese

↓

English

Japanese

↓

English

Business cards that already contain English should remain unchanged.

---

## Rule 2 – Application Language = Arabic

When the application language is Arabic:

* Preserve all Arabic text exactly as printed.
* Preserve all English text exactly as printed.
* Translate any other language into English.

Do NOT translate English into Arabic.

Do NOT translate Arabic into English.

Examples:

Arabic + English Card

↓

Keep both languages unchanged.

Japanese Card

↓

Translate to English.

Chinese Card

↓

Translate to English.

French Card

↓

Translate to English.

---

## OCR Confidence

Every extracted field should continue displaying its confidence score.

Translation should never overwrite the original OCR result internally.

Store:

* Original OCR Value
* Translated Display Value (when applicable)

This ensures future multilingual support without data loss.

Expand regional support by allowing users to select their default operating country.

---

**Kingdom of Saudi Arabia (KSA)**

---

Add the following countries to Settings:

* 🇸🇦 Kingdom of Saudi Arabia (KSA)

# Acceptance Criteria

The task will be considered complete only when:

* English remains the default application language.
* Arabic is fully implemented using professional Saudi Arabic terminology.
* The application correctly switches between English and Arabic.
* Arabic layout is fully RTL.
* OCR translation behaves according to the specified language rules.
* Original OCR data is preserved while translated values are displayed when required.
* Users can select from the eight supported GCC/MENA countries.
* Saudi Arabia is the default country for new users.
* Phone number, address, city, and country placeholders update automatically based on the selected country.
* Country-specific validation works correctly.
* Existing data remains unchanged when language or country settings are modified.
* The feature is tested on both Android and iPhone.
* Screenshots and implementation evidence are provided before marking the task as complete.
